# Pasada 2 — Sub-productos del concepto "Proyecto"

---

## De IDENTIDAD

### 2.1 Propósito

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | La razón de ser del proyecto. Responde a "¿para qué?" No es el qué (entregable) ni el cómo (plan). Es el cambio que se quiere ver en el mundo. |
| RESTRICCIONES | Debe ser concreto, motivador, medible indirectamente. Si no hay propósito, el proyecto es medio. |
| CONTRATO | El propósito se cumple o no cuando el proyecto termina. |
| NO-OBJETIVOS | No es el objetivo SMART, no es el business case. |
| PREGUNTAS ABIERTAS | ¿Quién define el propósito? ¿Puede cambiar durante el proyecto? |

**→ ATÓMICO**

### 2.2 Temporalidad

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | El proyecto tiene un principio y un final explícitos. No es eterno. |
| RESTRICCIONES | El tiempo es la restricción más visible — si no hay fecha, se diluye. |
| CONTRATO | El proyecto termina en T. Antes de T entrega; después de T se cierra. |
| NO-OBJETIVOS | No es la duración de la operación del resultado (el producto sigue vivo después). |
| PREGUNTAS ABIERTAS | ¿Un proyecto sin fecha es un proyecto o una ilusión? |

**→ ATÓMICO**

### 2.3 Singularidad

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | El resultado es único. No se ha hecho exactamente así antes. |
| RESTRICCIONES | La unicidad trae incertidumbre — no hay plantilla exacta. |
| CONTRATO | Producir algo que no existía antes. |
| NO-OBJETIVOS | No es originalidad por la originalidad. Puede parecerse a otros proyectos. |
| PREGUNTAS ABIERTAS | ¿Cuánta singularidad es suficiente para llamarlo proyecto? |

**→ ATÓMICO**

### 2.4 Recursos

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | Personas, tiempo, dinero, herramientas, conocimiento — todo lo que se consume para producir el resultado. |
| RESTRICCIONES | Son finitos. Se acaban. |
| CONTRATO | Con estos recursos y en este tiempo, se produce el resultado. |
| NO-OBJETIVOS | No es el resultado. Los recursos se gastan para producir algo. |
| PREGUNTAS ABIERTAS | ¿Qué pasa si los recursos se acaban antes del resultado? |

**→ SPAWN** → Personas, Dinero, Herramientas, Conocimiento

### 2.5 Incertidumbre

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | No se sabe exactamente cómo llegar. Es inherente a la singularidad. |
| RESTRICCIONES | Se puede reducir (planificar, investigar) pero no eliminar. |
| CONTRATO | Se navega la incertidumbre hasta que el resultado es claro. |
| NO-OBJETIVOS | No es ignorancia. Es conocimiento incompleto sobre el camino. |
| PREGUNTAS ABIERTAS | ¿Cuánta incertidumbre es aceptable al empezar? |

**→ ATÓMICO**

## De RESTRICCIONES

### 2.6 Triángulo de hierro

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | Tiempo, presupuesto, alcance — tres variables que se tensionan entre sí. Mueves una, las otras se mueven. |
| RESTRICCIONES | No puedes optimizar las tres simultáneamente. |
| CONTRATO | El proyecto promete un alcance en un tiempo con un presupuesto. |
| NO-OBJETIVOS | No es una ley física — se puede negociar. |
| PREGUNTAS ABIERTAS | ¿Dónde queda la calidad? ¿Es la cuarta pata o está dentro de alcance? |

**→ ATÓMICO**

### 2.7 Riesgo

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | Evento incierto que, si ocurre, afecta al proyecto. |
| RESTRICCIONES | No se pueden eliminar todos. Se gestionan: identificar, evaluar, mitigar. |
| CONTRATO | El proyecto explicita sus riesgos y cómo los maneja. |
| NO-OBJETIVOS | No es una excusa para fallar. Es una realidad que se gestiona. |
| PREGUNTAS ABIERTAS | ¿Cuándo un riesgo es aceptable sin mitigación? |

**→ ATÓMICO**

### 2.8 Dependencias

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | Cosas que tienen que pasar antes de que otras puedan pasar. Orden. |
| RESTRICCIONES | Si A depende de B, y B se retrasa, A se retrasa. |
| CONTRATO | El proyecto identifica y comunica sus dependencias. |
| NO-OBJETIVOS | No son excusas — son hechos del flujo de trabajo. |
| PREGUNTAS ABIERTAS | ¿Quién es responsable de las dependencias externas? |

**→ ATÓMICO**

### 2.9 Stakeholders

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | Personas o grupos con interés en el resultado del proyecto. |
| RESTRICCIONES | Pueden tener intereses contrapuestos. |
| CONTRATO | El proyecto identifica a sus stakeholders y gestiona sus expectativas. |
| NO-OBJETIVOS | No todos son clientes. Algunos solo observan. |
| PREGUNTAS ABIERTAS | ¿Cuándo un stakeholder tiene poder de veto? |

**→ ATÓMICO**

## De CONTRATO

### 2.10 Entregables

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | Lo que el proyecto produce. Pueden ser tangibles (un informe, un código) o intangibles (conocimiento, un proceso). |
| RESTRICCIONES | Deben estar definidos antes de empezar. |
| CONTRATO | Estos son los entregables. Cuando estén listos, el proyecto está completo. |
| NO-OBJETIVOS | No es el propósito. Los entregables sirven al propósito. |
| PREGUNTAS ABIERTAS | ¿Los entregables intermedios cuentan como entregables? |

**→ ATÓMICO**

### 2.11 Criterios de éxito

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | Cómo se sabe que el proyecto ha cumplido. |
| RESTRICCIONES | Deben ser medibles o al menos observables. |
| CONTRATO | El proyecto se evalúa contra estos criterios. |
| NO-OBJETIVOS | No es lo mismo que "todo salió según el plan". |
| PREGUNTAS ABIERTAS | ¿El éxito lo define quien financia o quien ejecuta? |

**→ ATÓMICO**

### 2.12 Valor

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | El beneficio neto que el proyecto aporta. Justifica el esfuerzo. |
| RESTRICCIONES | Puede ser económico, social, estratégico, personal. |
| CONTRATO | El valor del proyecto debe ser mayor que su coste. |
| NO-OBJETIVOS | No es el precio. No siempre es monetario. |
| PREGUNTAS ABIERTAS | ¿Quién decide si el valor justifica el coste? |

**→ ATÓMICO**

---

## De NO-OBJETIVOS

### 2.13 Proceso vs Proyecto

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | La frontera entre lo que se repite (proceso) y lo que es único (proyecto). |
| RESTRICCIONES | Un proceso puede contener proyectos. Un proyecto puede crear un proceso. |
| CONTRATO | Saber si algo es proceso o proyecto determina cómo se gestiona. |
| NO-OBJETIVOS | No son mutuamente excluyentes. |
| PREGUNTAS ABIERTAS | ¿Cuándo un proyecto se convierte en proceso (y viceversa)? |

**→ ATÓMICO**

### 2.14 Caos vs Proyecto

| Hueco | Respuesta |
|---|---|
| IDENTIDAD | Un proyecto sin control es caos. Demasiado control mata la adaptabilidad. |
| RESTRICCIONES | El proyecto necesita estructura pero también flexibilidad. |
| CONTRATO | El proyecto encuentra su punto entre el caos y la rigidez. |
| NO-OBJETIVOS | No es un péndulo que elige un extremo. |
| PREGUNTAS ABIERTAS | ¿Quién decide cuánta estructura necesita cada proyecto? |

**→ ATÓMICO**
