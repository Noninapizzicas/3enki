## La segunda mitad de la jornada (17:00-20:30 UTC) — capados y arreglos

### Incidente HERMES_TIMEOUT (proyecto B, 16:45-16:50)

Tras un "Ok" del usuario, el agente Hermes interpretó que debía seguir con la
tarea pendiente (restaurar `banco-ideas`) y se puso a trabajar con tools reales
(terminal, mv, write_file) durante >5 min → el relay (timeout 300s) cortó con
`HERMES_TIMEOUT` y escribió mensaje de sistema en la conversación. El agente
NO estaba colgado: el log del gateway mostraba tool_executor en acción. Fix:
`request_timeout_ms` 300000 → 900000 en modules_config (config se lee en onLoad
→ restart enki). Mismo patrón que invoke_agent: el timeout del esperador no
mata al trabajador.

### Revisión de capas ("Claude va pasando y capando" — directiva del dueño)

La integración de Claude Code venía capada por capas, cada una "config razonable"
por separado, juntas impedían que el agente trabajara:

1. **MCP `tools.include` a 3 tools** (`productos.list/get/search`) en
   `/home/hermes/.hermes/config.yaml` → el portal expone 448 pero el agente solo
   veía 3 → recurría a terminal crudo. Fix: eliminar el bloque include + restart
   del gateway de hermes (`sudo systemctl restart hermes-gateway` — lo lanza el
   dueño; el harness bloquea restart de gateway desde dentro de un gateway).
   Evidencia de MCP abierto: `sudo grep "registered" /home/hermes/.hermes/logs/agent.log`
   → `MCP server 'enki' (stdio): registered 420 tool(s)`. OJO: `GET /v1/toolsets`
   NO sirve para verificar (usa include_default_mcp_servers=False; solo lista ~25
   toolsets configurables).
2. **Permisos 755 sin g+w** en 7 módulos (banco-ideas, pipeline, correo,
   orquestador, motor-verif-commit…) — el motor Enki crea `drwxr-xr-x www-data`,
   el agente (grupo www-data) no puede escribir. Fix: `sudo chmod -R g+w /opt/enki/modules/`.
3. **Skills de Enki ausentes** en `/home/hermes/.hermes/skills/` (solo 4 genéricas)
   → el agente no sabía rail/cantera/patrones y "se perdía". Fix:
   `sudo cp -r /home/admin/.hermes/skills/enki /home/hermes/.hermes/skills/`.

Prueba de que el agente USA las tools de Enki (no terminal crudo): pedirle al
chat "Lista los ingredientes usando tu herramienta productos.ingredientes" →
en el log del gateway aparece `mcp__enki__productos_ingredientes` (firma de
éxito: prefijo mcp__enki__). Antes del fix: `Tool terminal returned error` con
Permission denied y comandos SO crudos.

### Fix portal event_based (PR #184) — "tool.handler is not a function"

El MCP → portal.handleCall → moduleLoader.executeTool (wrapper simple que llama
`tool.handler`). Las tools `event_based: true` (buscar_capacidad, detalle_capacidad
de cupula-eventos) NO tienen handler directo (su handler espera EVENTO del bus con
`event.data`) → UNKNOWN_ERROR "tool.handler is not a function". Fix:
`modules/_shared/motor/event-based-call.js` (publish + espera `<tool>.response`
correlado por request_id, timeout 15s) + portal.handleCall detecta
`toolDef?.event_based` y enruta por el helper. Alcance: ~847 tools con handler
directo funcionaban; solo las 2 event_based de la cúpula fallaban.
